# Documentation style guide

Prose in this repository follows the `humanizer` skill, in the language it is written in. Where
a document goes follows the `documentation` skill. Neither is restated here.

## Skill files

- `SKILL.md` opens with front matter: `name`, equal to the folder name, and `description`,
  starting with "Use when".
- A skill states rules as tables and short lists. A paragraph explains only what a table cannot.
- Examples sit in fenced blocks and show the rule being kept; a bad example appears only beside
  its good one.
- A skill ends with "Red flags" when there is a thought that reliably precedes breaking it.

## Words

English, British spelling in prose ("licence" the noun, "organisation"). Identifiers keep the
spelling the code uses, such as `license` in a checker constant.
